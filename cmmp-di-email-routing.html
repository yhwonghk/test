CMMP-DI Phase 2 Email Routing (Version 20260312) – Page 4
Without CMMP
Remark
  1. IMX need to configure the routing table to send emails targeting the registered SMTP domains of the B/D directly to CMMP-DI, bypassing GCN
  2. CMMP-DI need to configure all Edge Servers to accept emails addressed to the B/D via the GCN and IMX connectors
  3. If the B/D uses its own Internet Email Gateway, it need to configure the Gateway to route inbound Internet emails directly to CMMP-DI, bypassing its Domino server
  4. CMMP-DI needs to copy the CMMP routing table from the CMMP edge server to the CMMP-DI edge server
  5. GCN need move all registered SMTP email domains of the B/D to a Foreign Domain List, ensuring that emails routed via GCN to the migrated B/D are directed to CMMP-DI instead of the B/D’s Domino server
  6. CMMP-DI will need to remove the Smart Host feature between the CMMP-DI server farm & B/D Domino server farm so that all the registered SMTP email domains become authoritative in CMMP-DI.

Remark
  1. CMMP and CMMP-DI run in parallel with the same account on both sides: tmleung@uatbdoa.gov.hk exists in both systems, while bwhluk@uatbdoa.gov.hk is in CMMP only
  2. Scenario 1: in CMMP, tmleung@uatbdoa.gov.hk is a Mail Contact, so emails sent to it from CMMP are routed to the CMMP-DI mailbox. CMMP-DI then auto forwards a copy to the CMMP mailbox tmleung@cmmp.uatbdoa.gov.hk (alias as tmleung@uatbdoa.gov.hk)
  3. Scenario 2: emails are delivered to the CMMP mailbox tmleung@uatbdoa.gov.hk. CMMP-DI fetches them from this mailbox by EWS (Exchange Web Services) sync every hour, so an email can take up to about 1 hour to appear in CMMP-DI
